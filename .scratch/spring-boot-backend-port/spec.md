# Spring Boot Backend Port (Sirbull Pet Clinic)

Status: ready-for-agent

## Problem Statement

Sirbull Pet Clinic's React frontend was built against a legacy Python/FastAPI backend that handles clinic administration, clinical history, scheduling, multi-warehouse inventory, point-of-sale billing, analytical reporting, auditing, and a customer self-service portal. The target enterprise backend architecture is Java 25 with Spring Boot, Spring Data JPA, and Spring Security, but the existing frontend expects exact wire compatibility (`snake_case` JSON payloads, form-encoded OAuth2 token issuance, Spanish enum labels, computed read-only fields, and `{ "detail": "<message>" }` error payloads) while the backend must enforce strict DTO decoupling so sensitive entity fields are never leaked.

## Solution

Port the complete backend domain and API surface to Spring Boot while preserving the FastAPI wire contract (ADR-0001). Starting from the 28-entity JPA domain model, Spanish-backed enums with dual input parsing, and 28 Spring Data JPA repositories, implement dedicated plain-Java `@Component` mappers, security-focused DTOs (using `READ_ONLY` and `WRITE_ONLY` Jackson access rules), transactional services, and aggregate-grouped REST controllers across seven vertical domain slices, backed by stateless JDK `HmacSHA256` JWT authentication, `BCrypt` password hashing, IP rate limiting, OWASP security headers, and an automated `Auditoria` HTTP interceptor.

## User Stories

1. As a `Usuario` (`Administrador`, `Veterinario`, `Recepcionista`, or `Cliente`), I want to authenticate at `POST /token` using either my username or my email address and password, so that I receive a Bearer JWT containing my `sub` and `rol` claims.
2. As a security administrator, I want `POST /token` to enforce a rate limit of 5 login attempts per minute per IP address and reject inactive accounts, so that brute-force attacks and disabled credentials are blocked.
3. As a Visitante, I want to self-register at `POST /api/registro-cliente` with my username, password, DNI, full name, phone, and email, so that a `Usuario` with role `Cliente` and a linked `Cliente` profile are created atomically if my username, DNI, and phone are unique.
4. As a `Usuario`, I want to request a password reset at `POST /api/recuperar-password` using my email address, so that a 30-minute single-use token is generated, hashed with SHA-256 in `PasswordResetToken`, and any previous unused tokens for my account are invalidated without revealing whether my email exists.
5. As a `Usuario`, I want to reset my password at `POST /api/reset-password` using a valid, non-expired reset token and a new password, so that my password hash is updated with `BCrypt` and the token is marked as used.
6. As an `Administrador`, I want to list, create, update, and delete `Usuario` accounts (`/api/usuarios`), so that I can manage staff and customer roles and active statuses.
7. As an `Administrador`, I want the system to prevent me from deactivating or deleting my own active `Usuario` account, so that I cannot accidentally lock myself out of administration.
8. As an `Administrador`, `Veterinario`, or `Recepcionista`, I want to list and create `Cliente` records (`GET/POST /api/clientes`) with unique DNI and phone numbers and optional portal login credentials (`username` and `password`), so that pet owners are registered in the clinic and optionally granted portal access.
9. As an `Administrador`, I want to permanently delete a `Cliente` (`DELETE /api/clientes/{id}`), so that obsolete client records and their cascaded `Mascota` and `Cita` records are removed.
10. As a `Cliente`, I want to view my own profile (`GET /api/clientes/me`) and update my profile photo (`PUT /api/clientes/me/foto`), so that my personal information in the portal stays current.
11. As an `Administrador`, `Veterinario`, or `Recepcionista`, I want to register a `Mascota` under a `Cliente` (`POST /api/clientes/{id}/mascotas`), so that the patient's species, breed, birth date, photo, and active status are linked to its owner.
12. As an `Administrador`, `Veterinario`, `Recepcionista`, or `Cliente`, I want to list `Mascota` records (`GET /api/mascotas`) and update a pet's photo (`PUT /api/mascotas/{id}/foto`), so that staff can see all pets while a `Cliente` can only view and update photos for their own pets.
13. As an `Administrador`, `Veterinario`, or `Recepcionista`, I want to configure clinic working days, opening/closing hours, and slot duration (`15`, `30`, or `60` minutes) in `Configuracion` (`GET/PUT /api/configuracion/horarios`), so that appointment scheduling follows the clinic's operating hours.
14. As an `Administrador`, `Veterinario`, `Recepcionista`, or `Cliente`, I want to query available time slots for a given date and optional veterinarian (`GET /api/citas/disponibilidad`), so that past slots and already-booked slots are marked unavailable.
15. As an `Administrador`, `Veterinario`, `Recepcionista`, or `Cliente`, I want to schedule a `Cita` (`POST /api/citas`) for a `Mascota` with a service type (`Consulta médica`, `Control / Seguimiento`, `Vacunación`, `Baño / Aseo`, `Examen auxiliar`, `Cirugía`) and optional veterinarian, so that scheduling conflicts within the slot duration return `HTTP 409 Conflict`, staff-created appointments start in `Programada`, client-created appointments start in `Pendiente`, and `Examen auxiliar` appointments automatically create a `PENDIENTE` `OrdenExamen`.
16. As an `Administrador`, `Veterinario`, or `Recepcionista`, I want to list all appointments (`GET /api/citas`) and update a `Cita` status (`PUT /api/citas/{id}/estado`), requiring a non-empty `motivo_cancelacion` whenever transitioning to `Cancelada`, so that the clinic schedule is accurately tracked.
17. As a `Cliente`, I want to list my own pets' appointments (`GET /api/citas/mias`) and cancel my own appointment with a reason (`PUT /api/citas/{id}/cancelar`), so that I can manage my bookings from the customer portal.
18. As an `Administrador`, `Veterinario`, `Recepcionista`, or `Cliente`, I want to reschedule a non-cancelled `Cita` (`PUT /api/citas/{id}/reprogramar`) to a conflict-free slot, so that appointments can be moved without losing their record.
19. As an `Administrador` or `Veterinario`, I want to delete a `Cita` (`DELETE /api/citas/{id}`), so that erroneous appointments can be removed.
20. As an `Administrador`, I want to configure appointment pricing by service type and enabled payment methods in `Configuracion` (`GET/PUT /api/configuracion/pago`), so that appointment billing reflects current clinic rates.
21. As an `Administrador` or `Cliente`, I want to initiate a `Pago` for a `Cita` (`POST /api/citas/{id}/pagos`) using `YAPE`, `PLIN`, `TARJETA`, or `EFECTIVO` and process it (`POST /api/pagos/{id}/procesar`), so that a completed payment transitions a `Pendiente` `Cita` to `Programada` and issues a correlative `Boleta` (`BA64`) or `Factura` (`FA64`) via `ComprobanteSeq`.
22. As a `Cliente`, I want to list all `Pago` records for my appointments (`GET /api/pagos/mios`), so that I can review my payment history and electronic receipts.
23. As an `Administrador` or `Veterinario`, I want to record a direct `Consulta` for a `Mascota` (`POST /api/mascotas/{id}/consultas`) or attend a scheduled `Cita` (`POST /api/citas/{id}/atender`) with diagnosis, treatment, weight, and integrated `RecetaMedica`, `OrdenExamen`, and `ReferenciaMedica` items, so that attending a `Cita` marks it `Completada`, marks any linked `OrdenExamen` as `REALIZADO`, and prevents attending the same `Cita` twice.
24. As an `Administrador` or `Veterinario`, I want to update the result, observations, and status (`PENDIENTE`, `REALIZADO`, `ANULADA`) of an `OrdenExamen` (`PUT /api/examenes/{id}/resultado`), so that laboratory findings are recorded in the patient's file.
25. As an `Administrador`, `Veterinario`, `Recepcionista`, or `Cliente`, I want to view the consolidated clinical history (`GET /api/mascotas/{id}/historial`) as well as individual `RecetaMedica` (`GET /api/mascotas/{id}/recetas`), `OrdenExamen` (`GET /api/mascotas/{id}/examenes`), and `ReferenciaMedica` (`GET /api/mascotas/{id}/referencias`) lists for a `Mascota`, enforcing ownership checks when the caller is a `Cliente`, so that full medical records are accessible only to authorized users.
26. As a `Cliente`, I want to fetch all `RecetaMedica`, `OrdenExamen`, and `ReferenciaMedica` records across all of my pets in a single call (`GET /api/ordenes-medicas/mias`) enriched with `mascota_nombre`, so that I can view and print my medical orders from the portal.
27. As an `Administrador` or `Veterinario`, I want to record a `Vacuna` applied to a `Mascota` (`POST /api/mascotas/{id}/vacunas`), automatically computing `proxima_dosis` when `intervalo_dias` is provided and deducting 1 unit from `Disponible` stock in `Producto` and `StockAlmacen` when linked to an inventory `Producto`, so that vaccination records and vaccine stock stay synchronized.
28. As an `Administrador`, `Veterinario`, or `Cliente`, I want to query upcoming vaccination reminders due within the next 15 days (`GET /api/recordatorios`), filtered to the caller's own pets when the caller is a `Cliente`, so that booster doses are not missed.
29. As an `Administrador`, I want to create, update, and delete `ExamenAuxiliar` catalog items (`/api/examenes-auxiliares`), soft-deactivating (`activo = false`) any exam that already has linked `OrdenExamen` records upon deletion, while `Administrador`, `Veterinario`, `Recepcionista`, and `Cliente` can list the catalog, so that historical exam orders remain intact.
30. As an `Administrador`, I want to create, update, and delete master catalog records for `Proveedor` (`/api/proveedores`), `Categoria` (`/api/categorias`), `Familia` (`/api/familias`), and `Marca` (`/api/marcas`), while `Recepcionista` can also list them, so that inventory items are properly classified.
31. As an `Administrador` or `Recepcionista`, I want to generate the next correlative numeric SKU (`GET /api/productos/next-sku` in series `2026XXXX`), so that new products receive unique sequential SKUs.
32. As a visitor or authenticated user, I want to list `Producto` records (`GET /api/productos`) including computed category/family/brand/supplier names and `stock_por_almacen` breakdown, while an `Administrador` can create, update, and delete `Producto` records (`POST/PUT/DELETE /api/productos`), automatically initializing `StockAlmacen` on creation and recording an `AJUSTE` `MovimientoStock` if stock changes during product editing.
33. As an `Administrador` or `Recepcionista`, I want to manually add or subtract `Producto` stock (`PUT /api/productos/{id}/stock`), change a product's primary warehouse state (`PUT /api/productos/{id}/estado-almacen`), transfer partial quantities between warehouse states (`POST /api/almacenes/mover`: `Disponible`, `No disponible`, `Dañado`, `Vencido`), and inspect the kardex ledger (`GET /api/movimientos-stock`), so that every stock and state change is tracked with a `MovimientoStock` entry.
34. As an `Administrador` or `Recepcionista`, I want to list and register merchandise purchases (`GET/POST /api/ingresos`) from a `Proveedor` with `IngresoDetalle` line items, validating that expiration dates are not in the past, incrementing `Disponible` stock, updating purchase/sale prices and earliest expiration dates, and logging `INGRESO` `MovimientoStock` records; and as an `Administrador`, I want to delete/annul an `Ingreso` (`DELETE /api/ingresos/{id}`), reverting its stock and logging `ANULACION_INGRESO` `MovimientoStock` records.
35. As an `Administrador`, `Recepcionista`, or `Cliente`, I want to register a `Venta` (`POST /api/ventas`) with `DetalleVenta` items, validating that every `Producto` is in `Disponible` state, not expired, and has sufficient `Disponible` stock, validating the fiscal document (`8`-digit DNI or `12`-digit CE starting with `20` for `Boleta` `BA64`; `11`-digit RUC for `Factura` `FA64`), optionally redeeming an active `NotaCredito` with available `saldo`, atomically deducting stock, generating a pickup code (`SRB-XXXXXX`) and correlative receipt number (`ComprobanteSeq`), and logging `VENTA` `MovimientoStock` entries.
36. As an `Administrador`, `Veterinario`, `Recepcionista`, or `Cliente`, I want to view `Venta` records (`GET /api/ventas`, `GET /api/ventas/mias`, `GET /api/ventas/{id}`) according to my role and ownership, so that sales and online orders can be tracked.
37. As a `Cliente`, I want to request cancellation of my own `Pendiente` or `Confirmada` purchase before delivery (`POST /api/ventas/{id}/solicitar-anulacion`), transitioning the `Venta` to `Anulación solicitada`.
38. As an `Administrador` or `Recepcionista`, I want to transition a `Venta` state (`PUT /api/ventas/{id}/estado`) across allowed state transitions (`Pendiente → Confirmada | Cancelada`, `Confirmada → Entregada | Cancelada`, `Anulación solicitada → Cancelada | Confirmada`), automatically restoring stock to `Disponible` and logging `ANULACION_VENTA` `MovimientoStock` entries whenever a sale is `Cancelada`.
39. As an `Administrador` or `Recepcionista`, I want to process a post-delivery `Devolucion` on an `Entregada` `Venta` (`POST /api/ventas/{id}/devolver`), restoring stock to `Disponible`, logging `DEVOLUCION` `MovimientoStock` entries, and settling via `EXTORNO` or issuing a 180-day `NotaCredito` (`NC-XXXXXX`), as well as listing `Devolucion` (`GET /api/devoluciones`) and `NotaCredito` (`GET /api/notas-credito`) records.
40. As an `Administrador`, `Veterinario`, or `Recepcionista`, I want to query real-time dashboard KPIs (`GET /api/stats` and `GET /api/citas/proximas`) and analytical reports (`GET /api/reportes/ventas`, `GET /api/reportes/productos`, `GET /api/reportes/citas`, `GET /api/reportes/demografia`), so that clinic performance and patient demographics are visible.
41. As an `Administrador`, I want every successful mutating request (`POST`, `PUT`, `DELETE` under `/api/*`) and every successful `LOGIN` at `/token` to be recorded in `Auditoria` and queryable at `GET /api/auditoria`, so that all state-changing operations are traceable.

## Implementation Decisions

- **Foundation Already In Place**: All 28 JPA `@Entity` classes, 4 Spanish-backed enums (`RolEnum`, `EstadoCita`, `EstadoAlmacen`, `VentaEstado`) with JPA `AttributeConverter`s and dual input parsing (`fromValue` accepting both enum constant names and Spanish labels), `SNAKE_CASE` Jackson naming strategy, and 28 `JpaRepository` interfaces are implemented and verified.
- **Vertical Domain Slice Delivery**: The remaining layers (`dto → mapper → service → controller`) will be delivered in 7 vertical slices so the application compiles and passes tests at every step:
  - **Slice 1**: Security & Identity (`POST /token`, JWT filter, IP rate limiter, OWASP headers, CORS, `@RestControllerAdvice` returning `{ "detail": ... }`, `Auditoria` interceptor + `GET /api/auditoria`, `Usuario` CRUD, `/api/registro-cliente`, `/api/recuperar-password`, `/api/reset-password`).
  - **Slice 2**: `Cliente` & `Mascota` (`/api/clientes/**`, `/api/mascotas`, `/api/mascotas/{id}/foto`).
  - **Slice 3**: Scheduling, Configuration & Payments (`/api/configuracion/horarios`, `/api/configuracion/pago`, `/api/citas/**`, `/api/pagos/**`, `/api/examenes-auxiliares/**`).
  - **Slice 4**: Clinical Encounters, Medical Orders & Vaccinations (`/api/mascotas/{id}/consultas`, `/api/citas/{id}/atender`, `/api/mascotas/{id}/historial`, `/api/mascotas/{id}/recetas`, `/api/mascotas/{id}/examenes`, `/api/mascotas/{id}/referencias`, `/api/examenes/{id}/resultado`, `/api/ordenes-medicas/mias`, `/api/mascotas/{id}/vacunas`, `/api/recordatorios`).
  - **Slice 5**: Inventory, Catalogs, Warehouses & Purchases (`/api/proveedores/**`, `/api/categorias/**`, `/api/familias/**`, `/api/marcas/**`, `/api/productos/**`, `/api/almacenes/mover`, `/api/movimientos-stock`, `/api/ingresos/**`).
  - **Slice 6**: POS Sales, Billing, Returns & Credit Notes (`/api/ventas/**`, `/api/notas-credito`, `/api/devoluciones`).
  - **Slice 7**: Dashboard, Analytical Reports & Idempotent Seeding (`/`, `/api/stats`, `/api/citas/proximas`, `/api/reportes/ventas`, `/api/reportes/productos`, `/api/reportes/citas`, `/api/reportes/demografia`, and `DataSeeder` porting the demo users, clients, pets, exams, and 47 store products).
- **Security-Focused DTO Consolidation**: Each domain entity is represented by a canonical DTO in the `dto` package using `@JsonProperty(access = READ_ONLY)` for server-computed/output-only fields (such as `id`, `veterinarioNombre`, `examenAuxiliarNombre`, `citaMotivo`, `productoNombre`, `examenNombre`, `proveedorNombre`, `categoriaNombre`, `familiaNombre`, `marcaNombre`, `estadoAlmacenNombre`, `stockPorAlmacen`, `usuarioNombre`, `clienteNombre`, `vendedorNombre`, `comprobante`, `vigente`) and `@JsonProperty(access = WRITE_ONLY)` for sensitive write-only inputs (`password`), guaranteeing that `hashedPassword`, `tokenHash`, and internal JPA entity graphs are never leaked on the wire. Dedicated request/response DTOs are used where the payload shape differs from the entity (`ConsultaCreateDTO`, `CitaConMascotaDTO`, `HistorialMascotaDTO`, `OrdenesMedicasClienteDTO`, `DisponibilidadDiaDTO`, `HorarioConfigDTO`, `RegistroClienteRequestDTO`, `RecuperarPasswordRequestDTO`, `ResetPasswordRequestDTO`, `CancelarCitaRequestDTO`, `ReprogramarCitaRequestDTO`, `MovimientoAlmacenRequestDTO`, `CambioEstadoAlmacenRequestDTO`, `DevolucionRequestDTO`, `FotoRequestDTO`).
- **Plain-Java `@Component` Mappers**: Dedicated `@Component` mapper classes in the `mapper` package convert between JPA entities and DTOs without adding external mapping libraries to Maven.
- **Zero-Extra-Dependency Security & Wire Contract**:
  - JWT signing and verification use JDK `javax.crypto.Mac` (`HmacSHA256`) and `java.util.Base64` (`getUrlEncoder().withoutPadding()`), reading `SECRET_KEY` from environment/properties with fallback `"fallback-dev-sirbull-2026"` and 24-hour expiration (`1440` minutes), emitting `sub` (username) and `rol` (Spanish role string) claims.
  - Password hashing uses Spring Security's `BCryptPasswordEncoder`.
  - Role enforcement checks the authenticated `Usuario`'s `RolEnum` and returns `HTTP 403 Forbidden` with `{ "detail": "No tienes permisos suficientes para realizar esta acción" }` (or specific ownership error messages matching the legacy backend).
  - Global exception handling (`@RestControllerAdvice`) maps HTTP/business exceptions (`400`, `401`, `403`, `404`, `409`, `422`, `429`) to `{ "detail": ... }` JSON responses.

## Testing Decisions

- **What makes a good test**: Tests must assert external HTTP behavior (status codes, JSON response bodies in `snake_case`, database side effects observable through subsequent API calls or repositories, and security/RBAC enforcement) rather than mocking internal services or mappers.
- **Single Highest Testing Seam**: All slices will be tested through the **HTTP REST boundary using Spring `MockMvc` (`@SpringBootTest` + `@AutoConfigureMockMvc`) backed by the in-memory H2 database (`jdbc:h2:mem:idat_proyecto_db`)**. This single seam exercises the entire request lifecycle: `SecurityFilterChain`, JWT authentication, rate limiting, OWASP headers, Jackson `SNAKE_CASE` binding, Controllers, Services (`@Transactional` rollbacks), Mappers, JPA Repositories, and the `Auditoria` interceptor.
- **Modules to be tested**:
  - Authentication (`/token`), client self-registration, password reset flow, rate limiting, and `Usuario` CRUD.
  - `Cliente` & `Mascota` CRUD, photo updates, and client ownership isolation.
  - `Configuracion` (`horarios`, `pago`), `Cita` scheduling/conflict detection/rescheduling/cancellation, `ExamenAuxiliar` catalog (including soft-deactivation), and `Pago` processing with `BA64`/`FA64` receipt generation.
  - Clinical encounters (`Consulta`, attending `Cita`), `RecetaMedica`, `OrdenExamen`, `ReferenciaMedica`, `HistorialMascota`, `Vacuna` stock deduction, and 15-day `/api/recordatorios`.
  - Inventory (`Producto`, `next-sku`, `StockAlmacen` multi-warehouse state transitions, `MovimientoStock` kardex), catalogs (`Proveedor`, `Categoria`, `Familia`, `Marca`), and `Ingreso` creation/annulment.
  - POS `Venta` creation (stock/expiration/state validation, DNI/CE/RUC validation, `NotaCredito` redemption), state transitions, cancellation stock reversal, and post-delivery `Devolucion`.
  - Dashboard KPIs (`/api/stats`, `/api/citas/proximas`), analytical reports (`/api/reportes/*`), and `Auditoria` log recording.
- **Prior art**: Mirrors the 10 end-to-end integration test suites in the legacy Python backend (`test_auth`, `test_usuarios`, `test_crud`, `test_horarios`, `test_consultas`, `test_ordenes_medicas`, `test_vacunas`, `test_inventario`, `test_ventas`, `test_cliente_portal`) plus the existing `VeterinariaApplicationTests` JUnit 5 setup.

## Out of Scope

- Refactoring React components or UI logic inside `./frontend` (beyond pointing `./frontend` proxy/API port configuration from `:8000` to `:8081` when connecting the two).
- External SMTP server integration for password reset emails (retains local HTML file generation under `emails/` and dev-mode token return).
- Payment gateway SDK integration (retains simulated payment processing for `YAPE`, `PLIN`, `TARJETA`, and `EFECTIVO`).

## Further Notes

- Transactional operations (`@Transactional`) must roll back completely on any validation failure (`400`/`404`/`409`) so partial stock deductions or orphan records never occur (`RNF-05`).
